# 基于 LLM 与 GraphPrior 的缺陷报告优先级排序

本项目利用大语言模型（LLM）与知识图谱增强方法（GraphPrior），对众包测试报告进行优先级排序。GraphPrior 包含实例抽取融合、拓扑严重性打分、图向量混合去重与多样性排序四个阶段。

[English Documentation](README.md)

## 主要特性

*   **GraphPrior 四阶段流程**：实例抽取与融合、拓扑打分、混合去重、多样性排序。
*   **层次化聚类**：利用树状结构将缺陷报告细分为不同粒度的类型。
*   **多样性优先排序**：对报告进行排序，最大化前序报告中的缺陷种类覆盖率。
*   **自动评估**：统一计算 APSD 与 NDCG 指标，量化严重性发现效率与头部排序质量。

## GraphPrior 四阶段流程详解

GraphPrior 将“报告理解—严重性估计—重复抑制—最终排序”拆分为可组合的四个阶段，每个阶段都产生中间结构，供下一阶段复用。

### 阶段 1：实例抽取与融合（Extraction & Instance Fusion）

*   **输入**：原始缺陷报告文本（标题、正文、复现步骤、设备/版本信息等）。
*   **处理**：通过 LLM 从报告中抽取缺陷相关实例（功能模块、异常行为、触发条件、影响范围），并与知识图谱中已有实体进行对齐和融合，减少同义表述带来的碎片化。
*   **输出**：标准化后的实例集合与报告-实例映射关系。
*   **作用**：将非结构化自然语言转换为可计算的图结构语义表示，为后续拓扑打分和去重提供基础。

### 阶段 2：拓扑严重性打分（Topology-based Severity Scoring）

*   **输入**：阶段 1 生成的实例子图与实体关联关系。
*   **处理**：结合图中节点连接模式与结构特征，估计报告潜在严重性（例如影响路径长度、关键节点关联程度、风险扩散范围等）。
*   **输出**：每条报告的初始严重性分数。
*   **作用**：在进入最终排序前建立“图结构感知”的严重性先验，避免仅依赖文本表述强弱。

### 阶段 3：图向量混合去重（Hybrid Graph/Vector De-duplication）

*   **输入**：报告文本表示（向量）与报告关联子图（结构表示）。
*   **处理**：联合计算语义相似度与结构相似度，对候选重复报告进行判定与聚合；同簇内保留代表性报告，抑制重复样本对排序的干扰。
*   **输出**：去重后的报告簇与代表报告集合。
*   **作用**：降低重复报告对前序位置的挤占，提高有效审阅密度。

### 阶段 4：多样性优先排序（Diversity-first Ranking）

*   **输入**：阶段 2 的严重性分数与阶段 3 的去重簇结果。
*   **处理**：在高严重性优先的前提下，引入类别覆盖与信息增益约束，优先选择能带来“新缺陷类型”的报告，构建兼顾严重性与多样性的排序序列。
*   **输出**：最终优先级列表（用于人工审阅或下游缺陷管理流程）。
*   **作用**：让有限审核预算更快覆盖更多高价值缺陷类型。

### 端到端流程总结

1. 先将原始文本报告结构化（阶段 1）。
2. 再依据图拓扑估计严重性（阶段 2）。
3. 然后移除或合并重复报告（阶段 3）。
4. 最后生成兼顾严重性与覆盖率的优先序列（阶段 4）。

## 当前问题与已知局限

*   **打分稳定性依赖特定大模型**：当前排序与严重性打分仍强依赖所选 LLM 的推理能力与输出风格，不同模型/版本之间可能产生显著分数波动，尚未完全沉淀为与模型弱耦合的稳定算法。
*   **重复报告判定精度仍有提升空间**：图结构与向量相似度的混合去重在语义改写、跨模块描述或长文本场景下仍可能出现误判（误合并或漏检）。
*   **Token 消耗较高**：四阶段流程（抽取、融合、去重、排序）在中大规模报告集上会带来较高上下文与调用成本，影响运行时延与 API 费用。
*   **实验可复现性受模型版本影响**：即使固定提示词与参数，在线模型更新后结果可能变化，横向对比实验需要额外记录模型版本与时间。

## 使用方法

### 1. 配置环境
打开 `.env.example` 文件，填入实际配置信息并重命名为`.env`。

### 2. 数据准备
将缺陷报告 CSV 文件放置在 `reports/` 目录下（例如 `reports/app21.csv`）。

### 3. 运行排序
使用 `main.py` 运行排序流程。

**基本命令 (GraphPrior 模式):**
```bash
python main.py --app 21 --mode graphprior --repeat 1 --model gpt-5.2
```

**参数说明:**
*   `--app <int>`: 应用 ID（对应 `reports/app{ID}.csv`）。默认值: 21。
*   `--model <str>`: 模型名称（例如 `gemini-3-pro-preview`, `gpt-5.2`）。默认值: `gemini-3-pro-preview`。
*   `--mode <str>`: 运行模式。
    *   `graphprior`: GraphPrior 四阶段流程。
    *   `llmprior`: 标准 LLM 排序。
    *   `simple`: 简化版提示词。
    *   `direct`: 直接排序，不生成分类树。
*   `--repeat <int>`: 实验重复次数。默认值: 1。
*   `--file <path>`: 指定自定义 CSV 文件路径（覆盖 `--app` 参数）。

### 4. 输出结果
*   **Responses (`response/`)**: 保存 LLM 的原始文本响应。
*   **Results (`result/`)**: 保存解析后的最终报告排序序列。
*   **控制台输出**: 打印运行进度及最终 APSD / NDCG 评估分数。

## 代码结构

*   **`main.py`**: 程序入口。协调 查询 -> 解析 -> 评估 的全流程。
*   **`kg_service.py`**: 处理 Neo4j 连接、向量嵌入以及混合图谱检索逻辑。
*   **`llm.py`**: Google Gemini API 调用接口。
*   **`prompt.py`**: 管理提示词模板及上下文注入。
*   **`parse.py`**: 解析 LLM 输出的层次树结构，生成线性序列。
*   **`config.py`**: 配置加载器。
